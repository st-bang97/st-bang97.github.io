Research & Publications

Building Efficient GPU Servers, from Architecture to Full Systems

Vision

Reducing memory, data-movement, and execution bottlenecks in GPU servers

My research focuses on making GPU servers more efficient as memory capacity, data movement, and host-side execution increasingly limit large-scale AI workloads. Rather than working at a single layer, I address each bottleneck at the abstraction level where it arises—from architecture and full-system simulation to system software, optimized CPU/GPU kernels, and end-to-end training systems.

Research

GPU memory systems

I design memory-management mechanisms for GPU servers operating under memory pressure and oversubscription. My work covers prefetching, memory placement, migration, far-page-fault recovery, and device-side reclamation, with the goal of reducing host-mediated overheads and using GPU memory more effectively.

SAFE · ARIADNE · ReclaimX

Heterogeneous CPU–GPU execution

I study how CPU resources can contribute directly to GPU-centric workloads instead of serving only as overflow storage. In CPU-offloaded LLM training, I reduce host-memory traffic, restructure optimizer execution, and overlap CPU and GPU work so that host-side processing does not dominate the training critical path.

ReFlow · ReplayOpt

Workload-aware AI scaling

I use workload-specific sparsity and locality to scale AI training beyond conventional GPU-memory limits. My current work exploits expert-routing behavior in Mixture-of-Experts models and view-local working sets in 3D Gaussian Splatting to decide what data must reside on the GPU, when it should move, and when CPU-side work can proceed independently.

Systems expertise across the stack

I work across multiple independent abstraction levels and toolchains. My experience includes GPU architecture simulation with Accel-Sim, full-system simulation with gem5, NVIDIA GPU-driver and UVM development, SIMD-optimized CPU kernels, CUDA/PyTorch systems, and end-to-end server evaluation. I use these capabilities independently or together depending on where a system bottleneck is best addressed.

ReclaimX · ARIADNE · pNet-gem5
